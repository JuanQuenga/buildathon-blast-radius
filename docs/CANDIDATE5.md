# Candidate-5

One TPC-DS decision saved 14.864 simulated seconds on 197 registered holdout patches. Patched replay and scheduling on that decision took 6.591 CPU seconds. Across the entire holdout the net saving was 7.201 seconds, or 1.46 seconds per 40 patches. Neither the public sample nor tuning reproduced the saving. A single additional miss costs 300 seconds. This evidence supports a practice comparison and leaves the roughly 27-second gap to the leaders unexplained.

## Test costs and dependencies

TPC-DS class setup opens two DuckDB connections, loads the TPC-H and TPC-DS SQL fixture pairs and constructs tables from both sets of CSVs. The parent parses and serializes all 99 TPC-DS expressions. Each worker checks the metadata. For 57 queries it selects referenced tables from the 24-table schema, optimizes the expression, builds a logical plan and executes the plan with SQLGlot's Python executor. The parent converts result rows to a DataFrame, substitutes NaN for null, and calls the pinned comparison against a DuckDB reference result produced by transpiling the fixture SQL. Row order and column names matter. The comparison relaxes dtype and index type.

In the timing build, class setup used 1.912 CPU seconds. Across queries, parent parsing used 0.209, optimization 1.984, plan construction 0.288 and Python execution 10.734 seconds. The measured subcases used 26.114 CPU seconds including serialization, reference results and comparisons. These per-stage timers have different boundaries from the catalog and exclude worker startup outside the query. The image records timing in a separate run with branch and line monitoring disabled. The [99-row timing ledger](tpcds-query-cpu.csv) uses fixture order starting at one.

The parser budget test first accepts a literal SELECT and a SELECT with 500 columns. It then builds a 2,020,006-character query containing 10,000 depth-100 chains of equalities. Both large attempts tokenize all 2,020,000 tokens. With a million-node limit, tokenizing took 4.264 CPU seconds and parsing to the expected exception took 13.479. At 50,000 nodes the same operations took 8.217 and 0.591. These timings come from timing the pinned Dialect.tokenize and Parser.parse calls inside the original test in a two-core container. The test checks both error messages, then exercises a five-node exception and a successful subsequent unrestricted parse. The source profile put the three small assertion groups at about 0.010 CPU seconds combined. Replaying a reduced SQL string would omit the original threshold and post-error checks.

The generator memory test resolves every registered dialect. Per dialect it warms up 100 generator constructions, collects garbage, traces 1,000 further constructions and requires retained growth under 1,024 bytes after collection. Registry contents, generator construction and allocator state all matter. The 3.863-second TPC-H executor test uses the TPC-H tables and fixture metadata with the same multiprocessing helper. The 3.537-second optimized TPC-H test compares the DuckDB results for the original and optimized fixture SQL after transpilation and anonymous-column renaming. Both inherit the same setup as TPC-DS. Candidate-5 keeps static scheduling for these three tests. Setup and process costs take a substantial fraction of either TPC-H duration.

## Decision and failure handling

The build fetches the pinned source archive, installs the starter lock and records SQLGlot coverage per query in a parent and a spawned worker. It serializes the function, input expression, metadata and result within the measured regions. Full TPC-DS profiles contain executed lines and branch arcs. The parser profile contains executed lines. The selector consults line coverage over the entire changed statement and every statement between the first and last accepted edit. A query hitting any of those lines is a candidate for replay. The parser's two expensive checks form one group. A hit there leaves the test scheduled.

The gate accepts a single existing package file with local expression changes in selected parser, generator or executor methods. The complete file outside the method, method header, statement structure and bindings must match. Eligible differences include comparison or Boolean operators with unchanged operands, and replacing a call with a name it already reads. Class attributes, registry and cache edits, test or fixture changes, imports, and edits outside the recognized scopes keep the original selection. This excludes the documented Doris registry reset hazard. Setup or teardown coverage in the changed span also keeps the selection.

An eligible child receives a strict patch overlay. It runs the original parser assertion groups or the selected TPC-DS subcases, with a genuine spawned worker and the pinned DataFrame comparison. The selector requires successful teardown, import of the changed module, normal child exit and a completion receipt. Exceptions, worker failures, timeouts and incomplete receipts preserve the static plan. It skips replay where the recorded affected work exceeds seven CPU seconds or scheduling the remaining requirements gives no saving. Heavy jobs have a ten-second wall ceiling. The pass stops after 60 seconds or at 120 seconds from selector start, whichever comes first.

A separate collection-only fallback keeps the static full plan unless ordinary impact analysis produces a cheaper alternative and the single-file edit meets the body-only checks. It performs pytest collection on the patched overlay, with a six-second wall ceiling. Clean collection took 2.568 seconds wall. It covers pytest's actual collection hooks. The previously measured 0.3-second figure applied to imports in a prewarmed process.

## Validation and limitations

The exact starter flags passed with networking disabled, two CPUs, the 4 GB memory limit, 256 PIDs, read-only root, 64 MB tmpfs and UID/GID 65534. Two simultaneous patched TPC-DS replays with spawned workers both passed in one container. Separate checks exercised a failing executor worker, a passing parser assertion, a killed large parse, a collection import error and premature exit with status zero. All 16 inherited regression tests passed. The starter validator accepted the default image output on the official sample.

One development profile used branch-instrumented costs to gate runtime verification and did not attempt the useful replay. The release uses separately measured query costs. Its coverage comes from the pinned test running in isolation with one worker. Cache history, different worker assignments or effects transmitted by other tests can produce paths absent from an isolated trace. The scope and state checks reduce this exposure. The measurements cannot establish a zero miss probability. Rebuilding on a different CPU can also move a query set across the cost threshold.
